# Split bill (partial payments / multiple payers)

## GitHub Issues
- **Issue:** https://github.com/satisfecho/pos/issues/318
- **318**

## Problem / goal

Staff cannot split an order bill (partial payments, multiple payers, or separate tickets) while keeping a clear audit trail. Originally under umbrella #52 (“split invoice”) but never shipped as its own slice. Touches `Order`, Stripe PaymentIntents, staff “Mark as paid”, and Factura printing (`docs/0017-billing-customers-factura.md`); must stay consistent with VeriFactu numbering and join-table / table-group UX.

## High-level instructions for coder

- Document and implement a clear **split model** first: allocations by line, by amount, and/or by guest session — pick one MVP path and record the decision in docs.
- End-to-end MVP: at least one path where staff records **two payments for one order** OR a customer pays a partial amount, with reconciliation fields for reporting (no silent double-charge).
- Stripe: decide multiple intents vs partial capture; keep payment state auditable on the order.
- Factura / VeriFactu: one invoice per payer vs single invoice with split notation — keep numbering consistent with existing fiscal rules (`docs/0018-verifactu-fiscal-invoicing.md` / related VeriFactu work).
- Align UX with **table groups / join tables** (merged parties are the common split case).
- Coordinate with loyalty earn-once-per-order (#327) and price promos (#322) so discounts/earn do not double-count across payment legs.
- `CHANGELOG.md` entry; append **Testing instructions**. No secrets or live PII in fixtures.

## Implementation notes (010 feature coder)

- **MVP model:** split **by amount** (`docs/0071-split-bill.md`).
- Table `order_payment` + migration `20260726180000_order_payment_split.sql`; service `back/app/order_payment_service.py`.
- API: `GET/POST /orders/{id}/payments`, `DELETE …/payments/{id}`; mark-paid / finish settle remaining as one leg; unmark voids all legs; Stripe/Revolut write a settling leg.
- Order list includes `amount_due_cents` / `amount_paid_cents` / `amount_remaining_cents` / `payments`.
- Factura: still **one fiscal alta per order** when fully paid (deferred: per-payer invoices).
- Loyalty: earn only when order becomes fully paid.
- Staff UI: Orders payment modal — partial amount + payer label + record; full Mark as paid still settles remainder.
- Pytest: `back/tests/test_split_bill.py` (4 passed).
