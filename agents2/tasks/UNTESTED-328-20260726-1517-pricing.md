# Public pricing page (SaaS tier)

## GitHub Issues
- **Issue:** https://github.com/satisfecho/pos/issues/328
- **328**

## Problem / goal

`satisfecho.de` has no real pricing surface: `/pricing` redirects home and `/features` only vaguely mentions a SaaS trial/paywall with no numbers. Backend already exposes the live tier via `GET /saas/config` (`SAAS_TRIAL_DAYS=14`, `SAAS_PLAN_PRICE_CENTS=4900`, `SAAS_PLAN_CURRENCY=eur`) per `docs/0052-saas-signup-paywall.md`. Prospects need to see trial length and monthly price before signup.

## High-level instructions for coder

- Add a real `/pricing` route (or a pricing block on `/features`) that renders trial days and monthly price from **`GET /saas/config`**, not hardcoded copy that can drift from env.
- Show: 14-day free trial (no card), then flat monthly hosted price; state self-hosting / AGPLv3 as a zero-cost alternative vs hosted/managed.
- Short “what’s included” list (QR ordering, kitchen display, reservations, reports; loyalty only if already shipped — do not advertise unreleased features).
- Respect `SAAS_PAYWALL_ENABLED`: if false for a deployment, do not imply billing is active everywhere.
- Structure the page/data shape so a later multi-tier catalog does not require a full rewrite.
- i18n: DE / EN / ES parity with existing marketing language toggle; `CHANGELOG.md` entry; append **Testing instructions**.
- Docs: align with `docs/0052-saas-signup-paywall.md` and existing landing/features patterns.

## Implementation notes (coder)

- New public route `/pricing` → `PricingPageComponent` (marketing shell aligned with `/features`).
- Price/trial from `ApiService.getSaasConfig()`; `GET /saas/config` now also returns `plans[]` (`hosted_standard`) for multi-tier readiness while keeping flat fields for paywall/signup.
- When `enabled` is false, shows inactive-billing note; when true, shows active-billing note.
- Self-host card (€0 / AGPLv3) + included features (QR, kitchen, reservations, reports, loyalty).
- Nav links on landing + features; footer link; `PRICING_PAGE.*` + `LANDING.NAV_PRICING` in all nine locales.
- Smoke: `npm run test:pricing --prefix front`. Docs: `docs/0052-saas-signup-paywall.md`, `docs/testing.md`, README.

## Testing instructions

1. **API shape:** `curl -sS http://127.0.0.1:4202/api/saas/config` — expect `trial_days`, `price_cents`, `currency`, `enabled`, and non-empty `plans` with `id: hosted_standard` matching top-level price/trial.
2. **Page loads (not home redirect):** Open `http://127.0.0.1:4202/pricing` — URL stays `/pricing`; hero title is translated (no raw `PRICING_PAGE.*` keys).
3. **Live numbers:** Hosted card price and trial text match the config from step 1 (e.g. €49 and 14 days with default env).
4. **Paywall flag:** With default `SAAS_PAYWALL_ENABLED=false`, assert the inactive billing note (`data-testid="pricing-billing-inactive"`). Optionally set `true`, recreate `back`, and confirm `pricing-billing-active` instead.
5. **Self-host + CTA:** Self-host card present; register CTA goes to `/register`; GitHub link opens the POS repo.
6. **i18n:** Switch language picker to DE and ES — pricing strings update (no English leftover keys).
7. **Automated:** `BASE_URL=http://127.0.0.1:4202 npm run test:pricing --prefix front` (exit 0). Optional regression: `npm run test:features --prefix front`, `npm run test:landing-version --prefix front`.
8. **Backend unit:** `docker compose … exec back python3 -m pytest tests/test_saas_billing.py::test_plan_config_includes_plans_catalog tests/test_saas_billing.py::test_saas_config_endpoint_returns_plans -q`
